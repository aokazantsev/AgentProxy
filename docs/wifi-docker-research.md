## Факты

1. **USB в контейнер на Windows и macOS не пробросить.** Docker Desktop прямого проброса не умеет; с 4.35 есть
   USB/IP (Mac, Linux, Windows только на Hyper-V), на macOS нет полного сервера USB/IP. Рабочий путь — adb-сервер
   хоста: клиент adb в контейнере с `ADB_SERVER_SOCKET=tcp:host.docker.internal:5037` (или
   `ANDROID_ADB_SERVER_ADDRESS`). Сообщают, что сервер хоста должен слушать все адреса (`adb -a nodaemon server`, флаг
   `-a` при автозапуске сервера не передаётся) — это ломает обычную работу Android Studio и `slots.py` с сервером на
   `127.0.0.1`. Достаёт ли Docker Desktop до сервера на `127.0.0.1` хоста без `-a` — **не проверено, эксперимент 1**.
2. **`adb reverse` при удалённом сервере** ведёт порт телефона на порт той машины, где работает adb-сервер, то есть
   хоста, а не контейнера. Значит, порты устройств контейнер публикует на `127.0.0.1` хоста заранее, диапазоном:
   Docker не открывает порты на ходу. 32 устройства (`MAX_DEVICES`) — диапазон 8892–8923 при создании контейнера.
   Порт внутри и снаружи совпадает — устройство по-прежнему узнаётся по локальному порту. **Эксперимент 2.**
3. **Docker Desktop не сохраняет IP клиента** на опубликованных портах (Windows и macOS, и в режиме host networking с
   4.34; по сообщениям пользователей, официального описания нет — эксперимент 3): контейнер видит адрес шлюза или `127.0.0.1`. Отличать Wi-Fi-устройства по IP в контейнере нельзя, и фильтр
   клиентов по подсети тоже. Остаётся отдельный порт на устройство — как уже сделано для `adb reverse`.
4. **Брандмауэр Windows.** Программа без прав, которая слушает не `127.0.0.1`, вызывает окно брандмауэра; у
   пользователя без прав администратора Windows создаёт запрещающие правила при любом ответе (документация
   Microsoft). Нативному Wi-Fi-режиму нужно одно действие с правами администратора: правило на `python.exe`
   движка или на диапазон портов, профиль «Частная». У Docker Desktop правила на свой backend ставит его установщик;
   опубликованный на `0.0.0.0` порт обычно виден из сети, но бывает, что правила выключены.
5. **Сертификат.** `mitm.it` отдаёт сам mitmproxy, когда прокси на телефоне уже задан, — работает и по Wi-Fi. Android
   11+: браузер сертификат не ставит, только «Настройки → Безопасность → Шифрование и учётные данные → Установить
   сертификат → Сертификат ЦС» из скачанного файла. Android 7+: приложение доверяет пользовательскому ЦС только с
   `network_security_config` (как сейчас). iOS: профиль из Safari, установка в «VPN и управление устройством», затем
   включить доверие в «Об этом устройстве → Доверие сертификатам»; приложения iOS такому ЦС доверяют, кроме пиннинга.
   QR на странице монитора — адрес `http://mitm.it` и инструкция; Android не умеет задавать прокси по QR.
6. **Хуки Claude Code.** `SessionStart` поддерживает только `type: command` (HTTP-хуки на нём молча не срабатывают).
   Без Python на хосте команда хука — `curl` к API (есть в Windows 10+ и macOS). MCP уже HTTP.
7. **Лицензии.** mitmproxy — MIT, Python — PSF: образ можно публиковать (лицензии положить в образ). Docker Desktop
   бесплатен для личного использования и компаний до 250 сотрудников и $10 млн выручки; иначе нужна платная подписка.
   Бесплатные замены: Rancher Desktop, Colima (macOS), docker-ce в WSL2. Образ — GHCR (бесплатно для публичного
   репозитория, сборка в GitHub Actions).
8. **mitmproxy слушает режимами** `regular@<порт>` (`engine.proxy_modes`); у режима свой адрес
   (`regular@<адрес>:<порт>`), поэтому Wi-Fi-порты открываются на адресе сети, а общий и USB-порты остаются на
   `127.0.0.1`.

## Wi-Fi: как это выглядит в AgentProxy

- **Wi-Fi под управлением adb** (главный случай). `device_proxy enable` с режимом Wi-Fi ставит
  `http_proxy <IP ПК в сети>:<порт устройства>` без `adb reverse`: управление по USB, трафик — по Wi-Fi. Выключил Wi-Fi —
  трафик рвётся по-настоящему, это и есть настоящий офлайн из `deferred-ideas.md`. Устройство узнаётся по порту, как
  сейчас. `slots.py` менять мало: держатель устройства тот же, `serial` тот же.
- **Wi-Fi без adb** (iOS, чужой телефон). Устройство заводится по имени (`wifi:<имя>`), получает порт; монитор
  показывает IP ПК, порт и QR на `mitm.it`; человек вписывает прокси в настройках Wi-Fi.
- **Защита.** Порт в сети — открытый прокси для всех в этой сети, включая локальные сервисы ПК через прокси. Нужно:
  Wi-Fi-порт слушается, только пока устройство включено; клиентам с Wi-Fi-порта закрыт `127.0.0.1` ПК (по умолчанию);
  в нативной версии — фильтр по частным подсетям; режим выключен по умолчанию. API и MCP остаются на `127.0.0.1`.
- **IP ПК** меняется при смене сети: `status` и монитор показывают текущий, `device_proxy` перечитывает его на
  каждом `enable`.
- Рядом — «офлайн устройства» одним вызовом (обрыв всех запросов и потоков устройства), нужен при обоих способах.

## Рекомендация

Вариант **D по этапам**, Docker — только как способ поставки для macOS и Linux, если появится пользователь.
Причины: главная польза (настоящий офлайн, iOS и телефоны без adb) — в Wi-Fi, а он дешевле и лучше нативно (виден IP
клиента, нет VM); движок в Docker на Windows ничего не даёт, а прокси перестаёт работать, когда Docker выключен, —
это обычное состояние на этом ПК, а соседние треды и `slots.py` ждут прокси всегда.

### Эксперименты (с разрешения, Docker Desktop включает пользователь)

1. Клиент adb в контейнере видит устройства через `host.docker.internal:5037`, когда сервер хоста слушает только
   `127.0.0.1` (без `-a`).
2. `adb reverse tcp:8890 tcp:8892` с сервером хоста доводит трафик телефона до контейнера, опубликовавшего 8892 на
   `127.0.0.1`.
3. Телефон в той же Wi-Fi-сети достаёт порт, опубликованный на `0.0.0.0`; какой IP клиента видит контейнер.
4. Хук `SessionStart` с `curl` к API контейнера в Git Bash и PowerShell, и когда контейнер выключен.

## Решить до начала

- Нужна ли вообще macOS и кто её пользователь: без него этапы 2–3 — задел без проверки.
- Docker Desktop на рабочем ПК: лицензия работодателя (бесплатно до 250 сотрудников и $10 млн), иначе Rancher
  Desktop или Colima.
- Правило брандмауэра с правами администратора — допустимо ли одно окно UAC (сейчас программа ставится без прав
  принципиально).
- Wi-Fi-клиентам закрыть локальные сервисы ПК по умолчанию или оставить, как у USB (отладка локального бэкенда).
- Номер версии: этап 1 — 1.8 или 2.0.

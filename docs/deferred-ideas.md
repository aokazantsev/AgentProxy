# Отложенные идеи (после 1.0)

В план до 1.0 (`CLAUDE.md`) не входят. Берутся по решению пользователя.

## Проверки сети, которых нет при `adb reverse` (согласовано 03.11.2026)

Цель — проверки, которые нельзя сделать, пока трафик телефона идёт по USB. `adb reverse` остаётся основным
способом. Docker и мультиплатформа отложены, исследование — `wifi-docker-research.md`.

Что известно: Android проверяет интернет через глобальный прокси (`generate_204` и `gen_204` по HTTP,
`www.google.com` по HTTPS). HTTPS-проверка пользовательский ЦС не принимает, поэтому после переподключения Wi-Fi под
прокси сеть получает `PARTIAL_CONNECTIVITY` вместо `VALIDATED`. Правило `drop` на `/gen(erate)?_204` с `device` и
переподключение Wi-Fi оставляют у Wi-Fi `INTERNET` без `VALIDATED` — «Wi-Fi есть, интернета нет» (проверено на
Android 16).

### 1.8 — то, что нужно уже при USB

- TLS к хостам проверки интернета Android — без расшифровки, чтобы сеть под прокси была `VALIDATED`.
- Инструмент `device_network` с `state` для одного устройства (по его порту; другие устройства и ПК не задеты):
  - `online` — как обычно;
  - `offline` — новые соединения устройства закрываются сразу (`client_connected`), открытые — keep-alive, HTTP/2,
    WebSocket, SSE — рвутся (обёртка записи соединения из `SpeedLimits`, как у `events` с `close`);
  - `silent` — соединения не рвутся, а замирают: открытые без данных, новые без ответа (пропажа WAN без обрыва:
    проверка `pingInterval` и таймаутов);
  - `no_internet` — `offline` плюс обрыв проверки интернета Android и переподключение Wi-Fi: у Wi-Fi `INTERNET` без
    `VALIDATED`.
  - `duration_s` у всех — сам возвращает `online` (шаг «25 с без сети» одним вызовом).
  Состояние только в памяти движка: перезапуск возвращает `online`. `device_proxy disable` снимает его; `slots.py
  device release` ходит в adb мимо AgentProxy — нужен вызов API из `release` или предельный срок. Видно в
  `proxy_status` и `check_connection`, запросы в истории — с ошибкой «устройство офлайн», в журнале — порт без
  серийника. Через прокси DNS разрешает прокси: приложение видит закрытое соединение, а не `UnknownHostException`.
- Скилл: `device_network` и то, что проверка интернета идёт через прокси.

### 1.9 — Wi-Fi-режим

При `adb reverse` выключенный на телефоне Wi-Fi трафик приложения не рвёт: трафик идёт по USB, офлайн ненастоящий.

- `device_proxy enable` с `via: "wifi"`: глобальный прокси телефона — IP ПК в сети и порт устройства, без
  `adb reverse`. Управление по adb, трафик по Wi-Fi. По умолчанию `usb`, повторный `enable` переключает режим. Глобальный
  прокси действует и на мобильную сеть, а с неё IP ПК недоступен: выключенный Wi-Fi рвёт трафик и при включённых
  мобильных данных.
- Порт тот же, что у устройства по USB, но на IP ПК в сети; пускает только IP своего телефона (берётся через adb при
  `enable`) и слушается, только пока устройство в Wi-Fi-режиме. Устройства по USB и по Wi-Fi работают одновременно,
  `device`, история и правила — как сейчас.
- IP ПК — по подсети Wi-Fi телефона; ПК и телефон в разных сетях — отказ.
- Брандмауэр: программе без прав Windows ставит запрет на входящие. Когда правила нет, `device_proxy` сам открывает
  окно UAC и ждёт ответа; отказ — с пояснением. Правило узкое: `python.exe` движка, профиль «Частная», локальная
  подсеть. Запасной путь — пункт трея. Деинсталлятор снимает правило. Установщик остаётся без прав.
- Ручной прокси в настройках Wi-Fi (как в Charles) не делается: переход Wi-Fi → мобильная сеть этим планом не
  проверяется.

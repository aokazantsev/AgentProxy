# AgentProxy — инструкции для Claude

Поведение, установка и файлы — в `README.md`, прочитать перед правкой. Здесь только правила работы.

## Устройство

- Две части. **Программа в трее** (`src\*.cs`, C# 5, .NET Framework 4.8): значок, меню, журнал, настройки, обновление,
  отчёты о сбоях, присмотр за движком (`EngineSupervisor`: запуск, проверка `/api/status` каждые 5 с, перезапуск с
  паузами `RestartPolicy`). **Движок** (`engine\agentproxy`, Python 3.13 встроенный): mitmproxy, история запросов в
  SQLite, HTTP API и MCP на tornado, интеграция с Claude Code, командная строка.
- Движок запускается как `runtime\python\python.exe -I -m agentproxy --parent-pid <pid трея>` и сам выходит, когда
  трей умер. Коды выхода: 0 — штатно, 1 — падение, 3 — порт занят, 4 — нет папки данных.
- `Recorder` пишет завершённые запросы, сбои `CONNECT` и отказ клиента от сертификата прокси; SSE, ответы и тела запросов больше
  `max_body_bytes` пропускает потоком и сохраняет только начало тела. Поток держит только сжатый префикс
  тела до лимита (`StreamTap`), распаковка — один раз при записи, с ограничениями: не больше 64 МБ на выходе, окно zstd
  до 8 МБ, не больше 1000 членов gzip. Неизвестная кодировка или поломка до первого распакованного байта — тело хранится как пришло, как у mitmproxy;
  поломка или обрыв дальше — хранится распакованное начало с пометкой обрыва (размер на 1 больше). Повреждённый
  `flows.db` откладывается в `flows.db.broken`, история начинается заново. Запросы и CONNECT к своим портам защита
  помечает на заголовках (`OWN_PORT_MARK`), такие в историю не пишутся; не пишется и TLS, сказанный прямо порту прокси
  без CONNECT (настоящие клиенты прокси так не делают). Прочие ошибки SQLite при открытии (диск, права, блокировка)
  историю не трогают.
  История ограничена числом записей (`max_flows`) и объёмом (512 МБ: тела, адреса, заголовки; колонка `stored_bytes`, чистка раз в 100 записей или 64 МБ, файл до ~600 МБ); файл базы не
  сжимается, SQLite переиспользует место, WAL усекается (`journal_size_limit`, `wal_checkpoint` после очистки). WebSocket проходит сырым TCP (`websocket=False`): в историю попадает рукопожатие,
  сообщения не хранятся (`tcp_message` очищает их). `OwnPortsGuard.server_connect` не даёт соединиться через прокси с
  его же портами на loopback: иначе любой клиент прокси читал бы историю через API.
- MCP-инструменты и HTTP API — один набор (`service.TOOLS`): новый инструмент — запись в `TOOLS`, метод в
  `ProxyService`, строка в `SKILL.md` и README (тест сверяет `SKILL.md` с `TOOLS`).
- API слушает только `127.0.0.1` и отклоняет чужие `Host` и `Origin` (защита от DNS rebinding и запросов из браузера).
  Пароля на API и MCP нет сознательно: ПК с одним пользователем Windows (README, «Ограничения»). Хук старта сессии
  берёт из `/api/status` только числа и флаги, адреса строит сам.
  Остановка движка по API — только с токеном из `engine-runtime.json`.
- Интеграция с Claude Code (`engine\agentproxy\claude`): MCP-сервер в `~/.claude.json` (через `claude mcp add`, если
  CLI найден, иначе правкой файла; каждый вызов `claude` — до 25 с), скилл из шаблона `SKILL.md`, хуки в
  `~/.claude/settings.json`. Наши хуки узнаются по `agentproxy.cli` в строке `command` и по адресу
  `/claude/hooks/user-prompt-submit` — одинаково в Python (`is_ours`) и в запасной очистке деинсталлятора
  (`ClaudeConfigCleaner`). Команда хука старта сессии — короткий путь 8.3 к `python.exe` (работает и в Git Bash, и в
  PowerShell); если короткого имени нет и в пути есть пробел или спецсимволы — путь в одинарных кавычках и `"shell": "bash"`.
  Состояние — `claude-integration.json` в папке данных; `refresh` при старте трея переустанавливает интеграцию после
  обновления или если хуки не совпадают с ожидаемыми, и запоминает прежнюю версию.
- Уведомление об обновлении: хук старта сессии показывает «что нового» 3 дня после обновления и всегда — сессии,
  которая видела прежнюю версию (`--resume`); хук запроса (`UserPromptSubmit`, HTTP к движку) — один раз в каждой
  уже открытой сессии, которая видела прежнюю версию (`claude-sessions.json`). Текст берётся из `CHANGELOG.md` папки
  установки. Новые инструменты MCP открытая сессия видит только после перезапуска — уведомление это говорит.
- `claude --no-cli` в CLI — правка `~/.claude.json` без вызова `claude mcp`; нужен тестам и для ручной починки.

## План до 1.0

- Правила подмены: map local, rewrite, задержка и ошибка ответа, сценарии.
- Троттлинг запроса: ограничение скорости и задержка для выбранных запросов (просьба пользователя, 15.10.2026).
- Импорт правил из Charles: папка map local и её файлы в Windows-1251.
- Инструменты adb для прокси устройства: включить и выключить прокси, `adb reverse`.
- Подключение как в Charles: на телефоне в настройках Wi-Fi указываются IP ПК и порт прокси; затем сертификат по
  QR-коду со страницы монитора, адрес — служебный хост прокси (`mitm.it`), потому что прокси на телефоне уже задан.
  Решить до этого: прокси слушает сеть, а не только `127.0.0.1` (выключатель «слушать сеть», фильтр клиентов),
  входящее правило брандмауэра требует прав администратора, `adb reverse` остаётся вторым способом.
- SSE и WebSocket по событиям: запись появляется при открытии потока, события и сообщения дописываются по мере
  прихода, инструмент «ждать событие» по имени или тексту, живой просмотр в мониторе, правила подмены на событиях.
- Отзывчивые ответы для Claude: инструмент, который что-то меняет, возвращает итоговое состояние (id правила,
  условие, включено ли, сколько запросов совпало); у запроса видно, какие правила к нему применились; проверка
  подключения устройства (трафик идёт или нет, с какого времени, ошибки TLS); отказ называет причину и следующий шаг.

## Версии

- 0.x — каждое опубликованное состояние получает новый номер; 1.0 — первая рабочая версия.
- Номер версии в пяти местах: `engine\agentproxy\__init__.py`, `src\AppIdentity.cs`, три `AssemblyInfo.cs`; плюс
  верхняя запись `CHANGELOG.md`. Тест `test_version_consistency.py` ловит расхождение.
- `CHANGELOG.md` читает сам Claude у пользователя: после обновления записи версии приходят в сессию. Писать их для
  агента: что изменилось в инструментах, скилле и поведении, без внутренностей.
- До 1.0 Claude ставит, удаляет и переустанавливает программу сам; рабочую копию пользователь обновляет через трей.

## Сборка и проверка

- `py tools\runtime.py fetch` — встроенный Python и зависимости по хешам в `runtime\` (не в git). `lock` — пересобрать
  `requirements*.lock` после правки `requirements*.in`.
- `test.cmd` — тесты движка (pytest, включая сквозные с настоящим mitmproxy) и C# (`tests\csharp`). Сквозные тесты
  запускают движок на свободных портах во временной папке.
- `build.cmd nostart` — программа; `build-installer.cmd` — установщик `dist\AgentProxySetup.exe` и его sha256.
- Установщик — без прав администратора. Тихо: `AgentProxySetup.exe --silent` (из Git Bash ключи только через `--`,
  иначе Git Bash превращает `/silent` в путь). Удаление: `Uninstall.exe --silent`. Журналы — `%TEMP%\AgentProxy-setup.log`,
  `%TEMP%\AgentProxy-uninstall.log`.
- Перед релизом — установка поверх предыдущего релиза, проверка `agentproxy.cmd status` и журналов.
- Интеграцию с Claude Code проверять на копии конфигурации через `CLAUDE_CONFIG_DIR`, а установку — с
  `--option:claude=0` на машине, где интеграции нет. Поверх установки с интеграцией этот ключ её снимает (так же, как
  снятая галка в окне установщика); проверять там обычным `--silent` или с `CLAUDE_CONFIG_DIR` на копию конфигурации.

## Правила кода

- C#: штатный `csc.exe`, **C# 5** — нет `$"..."`, `?.`, `nameof`, `=>`-членов. Комментариев нет, один класс — один файл.
- Python: стандартная библиотека и то, что приезжает с mitmproxy; новые зависимости — только через `requirements.in` и
  `lock`. Комментариев нет.
- Журналы и отчёты о сбоях не содержат тел и заголовков запросов: только шаги, порты, ошибки.
- `.cmd` — CRLF и только ASCII; писать их python-скриптом или инструментом записи, не `sed`.

## Общее с другими pet-проектами

Проект — один из четырёх pet-проектов (AgentVpnGuard, DevMonitor, AgentGlow, AgentProxy), они устроены одинаково.

- **Общие файлы** взяты у AgentGlow 2.x с заменой `namespace` (с AgentGlow 3.0 у него и AgentVpnGuard часть из них ушла
  вперёд — `Installation`, `RunningApp`, `AboutForm`, `AppLog`, `UserDataPaths`; переносить по решению треда AgentProxy): `installer\setup\{SetupForm, Installation, InstallTarget,
  Payload, SetupOption, SetupField, InstallRequest, SetupLog}.cs`, `installer\common\RunningApp.cs`,
  `src\{AboutForm, CrashReportConsent, CrashUploader, CrashReport, AppLog, UserDataPaths, Autostart}.cs`,
  `installer\make-payload.ps1`.
- **Осознанные отличия:** установка без прав (папка пользователя, `UninstallRegistration` пишет в HKCU, манифесты
  `asInvoker`); тихий режим установщика и деинсталлятора (`SilentSetup`, `CommandLine`); `Update{Checker,Form,Release}.cs` —
  общие с AgentVpnGuard и AgentGlow (сверка sha256 по `digest` релиза, установщик в `Загрузки\AgentProxy-<версия>\`,
  «Установить сейчас» через ShellExecute), своё — `AppIdentity.UpdateSetupArguments` (`/silent /notify`) и `UpdateKeeps`.
  В DevMonitor их переносит его тред цикла техобновлений.
- Папку установки установщик и деинсталлятор считают своей только по маркеру `AgentProxy.install`, который пишет
  установщик, или по совпадению с записью в «Приложениях» — голого `AgentProxy.exe` мало: в репозитории он есть после
  `build.cmd`. Системные программы (`cmd`, `ping`, `taskkill`, `explorer`) запускаются по полному пути (`SystemTools`):
  установщик запускается из «Загрузок», и одноимённый exe рядом с ним выполнился бы вместо системного. По той же
  причине установщик и деинсталлятор первой строкой ограничивают поиск DLL папкой System32 (для библиотек, которые грузятся после старта `Main`; тест проверяет, что вызов первый).
- **Своё у проекта:** `src\AppIdentity.cs`, `installer\setup\SetupProfile.cs`, `installer\uninstall\UninstallProfile.cs`,
  `installer\payload.txt`, всё про движок.
- Меню трея: состояние; Claude Code; «Открыть монитор», «Подключить/Отключить Claude Code», «Перезапустить движок»;
  «Настройки…», «Журнал», «Проверить обновление…», «Запускать при входе в Windows», «О приложении…»; «Выход».
- Любая правка доводится до публикации: версия, `CHANGELOG.md`, тесты, установщик, проверка Защитником, коммит и push,
  Release с `AgentProxySetup.exe`, при необходимости README, скриншоты и страница на aokazantsev.ru/pets.

# История версий

Версии 0.x — рабочие заготовки: каждое опубликованное состояние получает новый номер. 1.0 — первая версия, которую
можно считать готовой.

## 0.3 — 2026-10-17
- Правила подмены вместо map local и rewrite в Charles — инструменты `add_rule`, `list_rules`, `update_rule`,
  `delete_rule` (HTTP: `/api/rules`). Действия: `respond` — ответ от прокси без обращения к серверу (текст или
  локальный файл `body_file`, код 200–599, заголовки), `rewrite` — правка заголовков запроса, кода, заголовков и тела
  ответа сервера, `drop` — обрыв запроса (HTTP/2 — сброс потока), `delay` и `delay_ms` у любого действия — задержка. `times` ограничивает
  правило первыми N запросами: так собираются сценарии «два сбоя, потом успех» (сбой — `respond` с кодом 500/503: обрыв `drop` клиент
  повторяет сам, счёт идёт по запросам, а не по действиям). Счёт срабатываний идёт с запуска
  движка. `respond` и `drop` с условием `host` работают и для HTTPS-хоста, который сейчас недоступен.
- Условие правила — `host`, `path`, `method`, `url_regex`; `host` и `path` работают как фильтры `list_flows`.
  `add_rule` сразу говорит, сколько записанных запросов подходит под условие (записи `CONNECT` не считаются).
  `proxy_status` показывает число правил: всего, включённых, действующих, и `problem`, если `rules.json` не
  прочитался, в нём были негодные правила или незнакомые поля.
- У каждого запроса в истории поле `rules` — какие правила к нему применились; `list_flows` и `wait_for_flow` с
  `rule` показывают только такие запросы; пометки `skipped`, `error`, `replaced`, `not_found` объясняют, что не применилось и
  почему. Монитор показывает правила у запроса и число действующих правил.
- Правила хранятся в `rules.json` в папке данных и действуют, пока их не удалят; хук старта сессии напоминает о
  включённых правилах. Скилл `agentproxy` описывает правила подмены.
- Правила держат в памяти не больше 64 МБ тела: ответ длиннее идёт без правки (у ответа без длины тело и размер в
  историю не пишутся), загрузка без
  длины больше 64 МБ под `respond` доходит до сервера целиком, клиент получает обрыв. Задержка отсчитывается после
  тела запроса и прерывается, когда клиент ушёл.
- API не принимает запросы, пришедшие через сам прокси, даже если приложение подменило ответ DNS: правила подмены
  иначе позволили бы ему прочитать файл с ПК.
- `get_flow` показывает тело в кодировке из `charset`; с `raw: true` — без форматирования JSON. В истории
  тело после правил: фрагменты для замен брать из запроса, к которому правила не применялись (поле `rules` пустое).
- История: тело в сжатии zstd из больше чем 1000 кадров распаковывается до тысячного кадра, как раньше у gzip.
- «Установить сейчас» запускает установщик обновления так же, как остальные утилиты автора (через оболочку Windows).

## 0.2 — 2026-10-16
- «Проверить обновление…» кладёт установщик в отдельную папку `AgentProxy-<версия>` в «Загрузках», а не рядом с
  другими файлами: случайная DLL оттуда не подгрузится в установщик. Окно обновления — общее с AgentVpnGuard.
- «Установить сейчас» перед запуском ещё раз сверяет файл с контрольной суммой. Если установщик закрылся, ничего не
  установив, окно говорит об этом и кнопка снова доступна.

## 0.1 — 2026-10-16
- Первая версия: прокси на mitmproxy, запись каждого завершённого запроса HTTP и HTTPS в историю, корневой сертификат
  для устройств. SSE, большие ответы и большие загрузки идут дальше сразу, в историю попадает начало тела (до 2 МБ). История —
  последние 5000 запросов, около 512 МБ. WebSocket проходит, в историю пишется рукопожатие.
- В историю пишутся и сбои: недоступный хост (`CONNECT failed`), приложение не доверяет сертификату прокси (запись
  `CONNECT` с ошибкой) — `list_flows` с `failed_only` показывает их.
- MCP-сервер `agentproxy` для Claude Code: `proxy_status`, `list_flows`, `get_flow`, `wait_for_flow`, `clear_flows`.
  Те же данные отдаёт HTTP API `/api/...`.
- Интеграция с Claude Code ставится и снимается одной командой: MCP-сервер, скилл `agentproxy`, хук старта сессии
  (состояние прокси) и хук запроса (сообщает уже открытой сессии об обновлении программы).
- Монитор запросов в браузере, только для просмотра.
- Программа в трее: присмотр за движком с перезапуском, окно журнала, настройки портов, проверка обновлений со сверкой
  контрольной суммы и установкой в один клик, отчёты о сбоях по согласию.
- Установка без прав администратора, тихий режим `--silent` для установки силами Claude.
